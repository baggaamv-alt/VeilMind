How it works

Remember. Generalize. Verify.

01

Remember

Raw engagement notes are stored only in that client's bank. A session working for one client can't open another client's bank. The request is refused and logged.

retain(bank_id="client-<id>", content, context, timestamp)
02

Generalize

When the engagement closes, reflect writes exactly one lesson. Names, figures, dates, quotes and identifying combinations are removed, and numbers become relative scale. If nothing useful survives, the answer is NO SAFE LESSON.

reflect(bank_id="client-<id>", query=DISTILL_PROMPT)
03

Verify

A separate check reads only the lesson text, with no client context, and asks whether someone could tell which client it describes. SAFE lessons are kept, UNSAFE ones are discarded, and rare patterns wait for a second engagement.

leak_check(lesson) → SAFE | UNSAFE → retain("firm-playbook")

Why it's different

Other tools lock the documents. Veilmind makes sure the shared layer never learns the secret.

Access walls

Permissions, encryption and audit logs sit on top of one store that still holds every client's raw data. Pooling everything into one context is exactly the setup that leaks.

reachable storage

Learning walls

The shared playbook is a smaller, deliberately scrubbed dataset. Ask it for another client's secrets and there's nothing to give, because the detail was never stored there.

never stored

Honest limits

This is a prototype. Automated checks reduce risk but don't guarantee confidentiality. Every verdict in the app is the actual result of that check.

defense in depth
